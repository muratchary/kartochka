# App Privacy ("nutrition label") — recommended answers

App Store Connect → App Privacy. Answer per the app's REAL behavior (below
reflects the current architecture — verify before submitting).

### Tracking
**Do you use data to track users?** → **No.**
Kartochka has no ad SDK, no IDFA, and does not share data with data brokers or
track across other apps/websites.

### Data collected
Everything is **linked to the user's identity** (tied to their account when they
sign in / enable cloud backup) and used for **App Functionality only** — never
for tracking or advertising. For users who never sign in, data stays on-device;
but because the optional sign-in / backup features DO transmit data, Apple
requires declaring these types:

| Data type (Apple category) | What / when | Purpose | Linked? | Tracking? |
|---|---|---|---|---|
| **Contact Info → Email Address** | Only if the user signs in (Apple/Google/email) | App Functionality | Yes | No |
| **Health & Fitness → Health** | Child's vaccination & growth records, when cloud backup is enabled | App Functionality | Yes | No |
| **User Content → Photos or Videos** | Milestone photos, when backed up | App Functionality | Yes | No |
| **User Content → Other User Content** | Child name, date of birth, milestones, notes, when backed up | App Functionality | Yes | No |
| **Purchases → Purchase History** | Subscription status (via RevenueCat) | App Functionality | Yes | No |
| **Identifiers → User ID** | Account / app-user ID (Supabase, RevenueCat) | App Functionality | Yes | No |

### Notes for the questionnaire
- For each type above: purpose = **App Functionality** only (do NOT tick
  Analytics, Advertising, or Product Personalization).
- **Privacy Policy URL:** https://kartochka.app/privacy
- Data processors: **Supabase** (optional cloud backup), **RevenueCat**
  (subscriptions), **Apple/Google** (optional sign-in). If you later add
  analytics/crash reporting, you must add **Diagnostics → Crash/Performance Data**.
- If you want the simplest defensible label and are willing to drop a feature:
  a fully on-device build with no sign-in/backup could declare **"Data Not
  Collected"** — but since backup/sharing are real (premium) features, the
  above is the correct declaration.
