# Kartochka v1.1 — Feature Plan

Status: DRAFT for review. **Do not start building until Android clears the
health-policy re-review** (don't change the app mid-review). Sequenced after
iOS 1.0.1 (onboarding back-nav fix).

## Governing constraint (the filter for every feature)
The app must stay classified as **Health & Fitness / personal parenting tracker**,
never **Medical** — because on Google Play a Medical classification forces an
Organization account the developer (personal account) cannot get, and would pull
the app. Test every feature: *"parent privately recording/organizing"* (OK) vs.
*"providing medical service/advice"* (FORBIDDEN).

- ✅ Allowed (Health & Fitness group): sleep, feeding/nutrition, activity, growth, keepsake/organizer.
- ❌ Forbidden (Medical group): medication/treatment tracking, symptom checker, disease/condition management, dosage/clinical advice, telehealth, doctor/EHR connection, vaccine *recommendation* engines.

All new copy keeps the disclaimer posture: "personal record-keeping, not a medical device."

---

## Feature 1 — Daily care logging (feeding / sleep / diaper)  ← centerpiece
**Why:** Vaccine & growth events are infrequent, so the app goes quiet between
them. Daily logging is the #1 most-requested baby-tracker feature and turns an
occasional-use app into a daily habit. Non-medical (Health & Fitness).

**Scope (keep simple, optimized for the under-2 stage):**
- **Feeding:** quick-add — breast (left/right/both, optional nursing timer), bottle (ml/oz), solids (note). Timestamp + optional note.
- **Sleep:** start/end or a running "asleep now" timer; nap vs night; auto-duration.
- **Diaper:** wet / dirty / both, timestamp.
- **Today view:** simple timeline + "last fed 2h ago", "last nap 45m".
- **History:** scroll by day; daily counts/totals.

**Design notes:**
- New **"Daily" tab** (or Home cards). **Age-gate it: show only for children under ~18–24 months** so it doesn't clutter the app for older kids.
- One-tap quick-add is the whole game — speed matters (parents log one-handed).

**Tech:** new Zustand store `careLogStore` (entries keyed by childId: type, subtype, startAt, endAt?, amount?, note?). Local-first; optional Supabase table `care_logs` with RLS mirroring existing tables. i18n in en/ru/ar/tr. Optional user-set feeding reminders via existing expo-notifications.

**Free vs Premium (recommend):** logging itself **FREE** (it's the engagement driver — everyone should build the daily habit). Premium gates **stats/charts + export** only.

**Policy:** pure logging. No "is my baby eating enough" assessment, no medical thresholds. Safe.

**Needs a real parent tester before ship.**

## Feature 2 — Shareable milestone cards
**Why:** Free growth/marketing engine + emotional hook ("will they recommend it").
**What:** generate a pretty branded image for a milestone/photo ("Aylin's first steps! 7 months") → native share sheet (WhatsApp / Instagram / Telegram — big in CIS+MENA). App watermark/link drives organic installs.
**Tech:** render styled view → image (view-shot) → expo-sharing.
**Pricing:** FREE (you want shares).
**Policy:** pure keepsake. Safe.

---

## Feature 3 — Engagement notifications (+ optional widget)
**Why:** retention; keep the app present between events.
**What:** opt-in weekly "your baby this week" local notification (age-based, **general** parenting info — non-prescriptive, non-medical). Uses existing notification infra.
**Widget (defer):** home-screen widget showing child age + next reminder. More native work (WidgetKit / Android) — lower priority.
**Policy:** general info only, no medical advice. Safe.
